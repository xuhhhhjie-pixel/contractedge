## 十二、拓展部分（任务书之外，自行增加）

### A. 公开夹具示例检查（`behavior_examples.py`，开关 `behavior_examples`）

**动机**：冒烟中已有测试检查一次都没有运行，因为开发例都没有能覆盖目标的测试。但公开输入里的夹具常常直接给出"触发 / 对照"的具体情况。全部 153 例中有 56 例带夹具。

**做法**：

1. **提取示例**：要求提取时一并提取示例，包括情况名、目标或保持、要观测的字段。期望值能在公开材料里逐字找到的记为"字面值"；找不到的记为"差异"：目标字段必须与原版不同，保持字段必须与原版相同。
2. **观测驱动**：执行器按协议写一个小程序，放在被 git 排除的目录里，不进补丁。它调用**生产代码**，为每个字段打印一行观测值。方法会提供一个可编译的骨架。
3. **原版校准**：驱动出现或修改后，先在原始版本副本上运行。字面目标值在原版上已经成立的字段（例如写死答案）会被剔除；保持字段必须在原版上成立。
4. **每次编辑后自动重跑**，把"观测值对期望值"反馈给执行器；提交前对没看过的失败提醒一次。

**保护措施**（来自真实运行的问题）：

- 字面期望值如果与该示例自己引用的记录中同名键的值冲突，降为"差异"。
- 已用 65% 时间仍没有校准成功的驱动时，停用示例，让执行器专心修复。
- 校准时限不超过剩余时间。
- 校准失败时，把驱动输出的最后几行反馈给执行器。

### B. 两组共用的去噪声修复（默认关，比较时两组同时打开）

| `force_clean` | 强制提交把临时文件带进补丁，导致 INVALID_PATCH | 强制提交前 `ce-submit --clean`：还原政策外的改动，删除新增文件 | 2182 的两个 INVALID 补丁剔除临时文件后，诊断重评都是 PASS |

### C. 诊断实验：上限诊断与"半上限"诊断

**这是测试流程，不是方法。** 真实环境中拿不到评测判据，所以这类运行不可能出现在实际使用中，也不计入方法成绩。它对应任务书 §14 的"人工修正要求的运行单列为辅助诊断"和"无提升时检查是哪个环节未生效"。

- **为什么要做**：方法组没有提升时，有三种可能：提取的示例不对；驱动没写好；或者执行器即使拿到正确反馈也修不对。只看最终通过率，分不清是哪一种。
- **怎么做**：只在已经查看过判据的开发例上进行。把案例评测包里的隐藏行为检查改写成示例（期望值取自判据）和驱动程序，通过一个仅供诊断使用的入口（运行规格中的 `gold` 字段，"金标"即评测侧的标准答案）直接交给执行器，其余流程与方法组完全相同。
- **分档**：

| 档位 | 示例 | 驱动 | 用途 |
|---|---|---|---|
| L0 共同基础组 | 无 | 无 | 对照 |
| L1 方法组 | 方法自己提取 | 执行器自己写 | 方法的真实表现 |
| L2 半上限诊断 | 来自判据 | 执行器自己写 | 检验"驱动"这一环 |
| L3 上限诊断 | 来自判据 | 来自判据 | 检验"执行器拿到正确反馈能否修对" |

- **结果**：
  - L3：2117 3/3、KEDA 3/3，**共 6/6**；同条件 L0 为 0/4。
  - L2：2117 2/3、KEDA 2/2。4 次通过中有 3 次根本没有校准成功的驱动，执行器只是在开头看到了正确的期望值。
- **结论**：执行器拿到正确的行为信息就能修对；驱动回路是次要的；**瓶颈在于方法自己能否从公开材料中提取出正确的示例**。L2 和 L3 用到了判据，只说明上限，不是方法能达到的成绩。

**失败分析**：

## 十三、风险

1. **修复率没有结论**：开发例少、每组 3 次，四个开发例的判据都已查看过。
2. **适用范围窄**：示例检查只在 Go、R4 类、带公开夹具的案例上试过；Ginkgo、Helm、kustomize 等测试形式不支持。
3. **错误的示例会误导执行器**：已加冲突检查和原版校准，但不能完全排除（换个字段名就绕过了冲突检查）。
4. **共有的累计 token 预算**：开发集 24 次运行中有 3 次因此中止（方法组 2 次、基础组 1 次）。
5. 预算参数都是暂定值，正式对比前需要冻结。
6. **运维**：11-12 14:11，实验用 Docker 守护进程 `ceofficial-docker.service` 在同时跑 3 个隐藏评分时被 OOM 杀死；经确认后重启，受影响的评分已逐个重评。此后隐藏评分一律一次只跑一个。

2. 第十二章 B 的三项公共修复，是否在正式环境中对所有组生效，由谁来改。
3. 每次运行的累计 token 预算是否调整。
4. KEDA-7777 判据的修订，以及按"期望值能否从公开材料推出"做一次案例审计。
5. 留出集和正式对照：
   - 按规则另选 6–8 个没有查看过判据、带夹具的 Go 案例。每例需要先零模型准备运行时，约 15 分钟。
   - 每组每例 3 次，约 40–50 次运行，约 50 元。
   - 是否按任务书 §11 另设同预算的"主动定向测试"对照组。
6. 改造四（关系扩展）是否仍在本轮范围内。
