# ContractEdge 0.4.3系统优化验收

状态：本轮核心改动、工程回归及有限开发核验已交付；效果提升未获充分证据。正式150条与消融不在本轮范围内。

## 三项核心改动

1. **Diagnosis：让相关证据实际进入诊断。** 有界源码池按文件交错，需求中的标识帮助定位窗口；对高度重叠窗口和同文件重复采用软惩罚。精确路径与同一缺口查询可只读扩展到公开Broken源码，不能扩大编辑权限，也不能把关联当作已验证调用边。完整请求裁剪记录丢弃原因，保留证据身份。结构合法后汇总可独立判断的关系错误，不自动修正模型因果结论。
2. **Semantic ChangeSet：把义务和约束传到实际编辑。** 复用O/A/E/V/C/P及现有依赖、触发、保持字段；真实TopoMen DefaultAgent接收当前目标文件和有界、已验证的只读接口证据。操作覆盖只说明计划操作被执行，不冒充语义正确。保留原子应用、范围限制和原始Broken补丁基线。
3. **执行反馈：只用当前观察解除义务。** 公开合同明确渲染、行为、构建及不可观察的边界；声明输入与实际JSON观察可做确定性字段比较。编译通过不能证明运行时行为。PASS/FAIL都须引用当前snapshot的精确观察原文；未解决和保持义务跨轮次保留，明确不可观察标记不能因重诊断丢失。反馈关联P/C/V/E及实际观察，未知归因结束，不能盲目重试。
