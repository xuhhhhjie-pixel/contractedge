# 固定46槽父侧评分协议修正

原方法仍为0.6.45、基线0.5.5；本修正仅涉及共同父侧评分和记录承接，不改变方法源码、模型、预算、原生消费者、公开探测或隐藏评分器。

## 已确认根因

原冻结score_case入口以0表示PASS、1表示正常负向结果、2表示工具错误。外层旧wrapper却把所有非0退出改写SCORER_ERROR。KOPF基线已有完整SEMANTIC_FAIL，退出1；队列因此错误停止。该案例的方法实际失败，不能当成通过，也不需要重跑评分或模型。

## 修正与边界

新wrapper按冻结约定区分负向结果与基础设施错误；PASS配非0或负向结果配错误退出等不一致情况仍拒绝。只读兼容仅支持已知旧wrapper的准确SHA256，逐项核对方法回执、补丁、原评分工具/数据、已完成checkpoint、日志和score字节。旧result.json的SCORER_ERROR原样保留，补充解释为原生SEMANTIC_FAIL；未知/未完成评分不能变为终态。

原panel、原records和原输出目录保持不可变。父侧修正版登记引用完整旧前缀及摘要，沿用原46个槽位ID、案例、顺序、源、配置、种子和12调用/2编辑/150元共用账本；在新目录承接全部旧终态，不能筛选PASS或删除失败。已完成的槽位不会重新派发。新增身份仅明确父侧协议修订，不能当作新方法尝试或重新计数。

共享方法环境中只允许父侧fixed_panel权限核验模块的摘要差异；修复worker、原生消费者和116/71方法文件保持。所有原前置门继续执行，B不提前开放。原始5槽在零调用回放中保持4个PASS，KOPF基线保留真实SEMANTIC_FAIL；没有重跑grader或模型。
