# 公开检查绑定与场景协议：0.6.45交付说明

## 目的和范围

落实用户确认的第一优先项：先修复可确证的信息传递断点，再接通固定开发面板，根据同版结果判断是否继续修改组件。本轮为通用公开检查协议修复，零模型HTTP，不运行正式150或隐藏评分。

基线为本地4582146的0.6.44；其已上传GitHub PR #15。默认运行目录仍保留0.6.40。本轮不继承0.6.44的真实修复成绩。

## 根因、修复与边界

|断点|修复|保持的判断边界|
|---|---|---|
|注册检查已在输入能力中，计划schema只识别method_behavior_probes|两种声明进入同一检查目录，三个义务字段均能输出真实检查引用；注册路径提示版本v1.1.14|不替模型添加绑定；无注册路径保持原提示版本|
|检查覆盖字段仅随traceability出现|存在检查时允许明确coverage与rationale；实际绑定必须声明覆盖关系|ALL_OF只表达有限具体谓词，NECESSARY_ONLY不能证明全义务PASS|
|观察缺少scenario，验收要求匹配|三个开发例子使用既有执行场景selected-and-preservation；六例面板使用既有public-requirement-panel；逐检查显式列举成员|成员由冻结公开断言产生；稳定性检查覆盖多个成员，不能从check ID猜场景|
|结构化覆盖信息进入反馈遇到旧schema|scenario使用既有字段，成员列表保留于带摘要正文|保留原反馈schema，错误场景/正文即使重新摘要也不能通过可信profile校验|
|未知/错场景绑定能通过READY前计划校验|语义校验拒绝未注册ID、场景不一致、缺覆盖说明|两个声明源出现重复ID时拒绝，不覆盖；旧无能力声明的独立兼容入口保留原范围|
|READY和修订只比较consumer，沿用旧检查定义|对比当前与保存的完整公开检查/探测声明，再构造请求|删除检查、换场景/成员/断言/观察器摘要均在新增模型调用前拒绝|

源码位置：contracts/public_checks.py、changeset/prompt.py、changeset/validate.py、execution/public_observer.py、development/method_panel_fixtures.py、orchestration/repair.py。synthetic provider显式编写新场景绑定；真实模型输出不由适配器补写。隔离验收脚本精确核验新提示版本，拒绝旧版本/错序/错消费者/多余调用。

## 下一步：接通固定46槽面板

现有scripts/run_reliability_delivery.py按旧worker/batch.json协议驱动；scripts/run_isolated_method.py仅接受ISOLATED_DEVELOPMENT_VALIDATION且counts_in_46_slot_panel=false。下一步应增加严格的固定面板登记适配，不能直接把false改成true，也不能把24个合成格或单条资格验证转填成46槽结果。

1. **恢复并只读核验原登记。** 固定A7、B10、KOPF/Alert重复和KPT/Alert公开失败续修；保持A+B34、重复4、续修8，共46。核验原基线源码、当前候选、配置、公开数据、种子和评分器身份及B曝光账本。基线是否能在当前隔离协议下等价运行，必须先离线证明；不兼容时明确停止，不能拿候选实现代替基线。
2. **添加面板登记与一次性派发适配。** 在独立面板入口验证slot_id、case/group/repeat/variant、source/config/probe/dataset/baseline摘要、attempt_id和持久claim。方法侧仍只见公开白名单；parent-only评分仅在候选封存后执行。资格验证入口仍拒绝面板冒用。
3. **先做零HTTP调度与恢复测试。** 证明完整46槽唯一且不替换、不重复、不混版；中断/未知响应不自动重发；评分恢复不再生成补丁；A/重复/续修验收前B保持关闭。保存输入回放同时核验当前检查身份、计划和执行请求。
4. **冻结后再执行原登记。** 同版完成A、重复和真实续修；满足既定门槛才打开预选B。失败或UNKNOWN如实保留；若暴露新通用缺陷，先定位最早断点、回放修复并建立新版本，旧成绩不迁移。150元累计账本继续共享，预算不足保留未运行，不改变分母。
5. **汇总后再决定组件优化。** 先分清检查丢失/错绑、模型判断、具体实现、公开观察不足、评分或环境问题。只有证据明确指向某组件，才进行相应最小修复。实现G0—G6最终聚合与干净克隆运行验收后，才可进入正式准入。

## 能作出的结论

本轮通过时，证明注册检查能够以明确场景进入计划、观察、反馈与受控续跑，并且错误绑定仍会被拒绝。它不证明模型会充分利用每个检查，也不证明独立修复率已提高。正式准入仍为false；是否需要进一步修改诊断、计划或执行，必须由后续固定同版面板的完整结果决定。
