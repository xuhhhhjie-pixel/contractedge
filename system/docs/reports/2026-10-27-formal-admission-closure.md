## 准入程序的使用

程序在管理/评分侧运行，不进入模型沙箱。示例：

```bash
python scripts/assess_formal_readiness.py \
  --manifest outputs/planning-helper-contracts-20261027/FINAL_ADMISSION_MANIFEST_v2.json \
  --output /path/to/new-formal-readiness.json
```

退出码0表示证据满足准入，1表示未满足；输出文件必须是新路径，避免覆盖旧验收记录。运行中的records追加后，旧manifest摘要会过期；应在队列稳定时为相同登记产生新证据引用，保留旧报告。该程序不发起模型请求、不重新执行评分、不启动正式实验、不修改费用账本或运行版本。

manifest绑定系统目录、交付快照、原固定面板和原始records。G0—G6报告必须记录当前源码/配置/数据/登记身份、检查器、执行时间、检查输入及每项检查的保留证据；仅写一个PASS不被接受。固定面板状态由现有严格终态验证器重新核对，不能上传手写结果表代替。独立PASS但公开明确FAIL不能作为验收通过；UNKNOWN继续保留。合法的独立失败仍是失败结果，不会被误报为基础设施错误。

程序核查可信检查器产物的身份和完整性；文件摘要不能证明任意人工报告的语义正确。因此，原方案实现映射和必要正反例仍须按原计划复核，不能靠新程序补写PASS。

交付工具与新增测试位于方法源码之外；原有方法、配置和已冻结派发/评分工具未改，原46登记仍有效。原方法的2177项+91子测试及实际隔离资格继续绑定原始精确源码；新增准入程序单独验收，不冒充它已参加此前的全套运行。
