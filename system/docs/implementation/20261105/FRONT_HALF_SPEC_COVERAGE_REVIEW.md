## 3. 本次实质补齐了什么

1. **把概括的“撤掉重复额度”落实到完整调用链。** 除原40条、24k／48k、两次补证，补列初次抽取、范围匹配、局部helper、依赖目标、首诊子窗口、前提审查12项以及ChangeSet返回补查的入口。
2. **明确不能误删的现有正确行为。** 无损同请求共享、真实请求与工具资源限制、路径／来源／版本核验、因果与权限校验、未引用公开观察保留和旧版本恢复边界继续保留。
3. **补齐模型输入和输出两端。** 原始需求与已接纳观察不得因归一化或未引用而消失；额外输出数量门和纠错尾截须处理，但不能把它们误说成输入源码截断。
4. **明确配置及兼容路径退出方式。** 不能只改新工具，仍让CLI、benchmark、恢复、提示或旧默认值把已取消的规则带回。

这些代码入口中，有些是历史实验已经复现的缺陷，有些是本次静态核对发现的实施遗漏风险。不能声称每个上限都已造成某个真实失败，也不能将新增验收数量称为新增模型收益。
