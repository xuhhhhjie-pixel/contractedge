# 完整生产路径、跨分支计划与公开行为验证

依据：0.4.7公开KPT计划只改runValidators，公开承认mutator未覆盖；构建通过但6项检查UNKNOWN，独立失败只作为结果记录，不读取隐藏断言或Fixed。ACK公开轨迹仍缺机制证据。正式150及消融不派发，80元共享总账不重置。

目标不是强制所有案例PASS，而是将公开源码中可定位的相邻生产分支纳入取证/计划，并使方法侧公开行为探测在同一Broken/候选之间给出真实反馈。仍需保留无法判断的义务。

1. 零调用复现生产分支遗漏发生在提取、候选池、最终请求还是计划；只针对可复现机制改动。建立受限静态生产路径清单，标记词法关联和未覆盖边界，不宣称完整调用图。
2. 计划对实际提供的相关路径明确修改、保持、无关或未解决；引用真实证据和修改/开放义务。校验器防漏项、假引用与无修改的虚报覆盖，不把格式齐全视为语义正确。沿用原有纠错、调用和轮次限制。
3. 增加可审计的方法侧探测入口，与冻结公开launcher/独立评分分离。探测由公开需求和公开API导出，可信探测代码在模型修复前冻结、同一份运行于Broken/候选；不能写入正式候选补丁，不能读取私有材料。构建、行为不满足、环境/探测错误分别记录。先实现并真实验证KPT配置资源所属函数隔离/后续可见/最终资源保存的公开探测，明确这只是首个已支持家族而非150通用覆盖。
4. 新负向回归先RED后修复；完整工程回归后冻结源码/配置/探测身份。先零调用重放历史候选，验证探测是否发现公开可解释的不满足；只在方法反馈可用后做有限真实开发验证，保持RW130成功回归。候选固定后独立评分，失败不用于读取隐藏答案反向调补丁。
5. 完成审计逐项检查真实生产路径上下文、计划处理清单、探测Broken/候选对照和反馈接通、最终独立结果、成本及未运行记录。若修复率未提升如实报告，不以工程测试或一条成功代替。
