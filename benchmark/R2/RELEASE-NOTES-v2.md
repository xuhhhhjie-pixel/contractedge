## 2. 本版本改了什么（方法层面）
评估侧判据由“固定场景 + 夹具常量/整句比较”改为“从需求推导的行为判断 + 评估侧新增或隐藏场景”：候选多输出日志不再导致语义失败，无合法观察时归为基础设施错误（绝不判通过），重复键判失败；去掉超出需求的断言；若干案例增加了只在评估侧可见的判别场景，或把观察点从被测实现的私有函数移到更外层入口。评分器工具未改。每个冻结案例在冻结前重跑 GT 与 Broken 各一次（21 案共 42 次）：GT 全部通过、Broken 全部语义失败，逐 cell 与此前记录一致。

## 4. 剩余风险（冻结不等于这些风险不存在）
1. **已知的评分器误收**：8227、27136 各有 1 个已知的错误实现可通过（评估侧场景覆盖缺口；细节保存在私有复核记录）。另有个别错误实现在离线观察下与参考不可区分（7777、27136），不算评分器缺陷但会被判通过。
2. **INFRA_ERROR 分类（评估协议规则）**：408、824、13937 中，候选自己破坏了控制格（如强制明文 HTTP、丢掉必要的更新、不再加属主）时评分器记基础设施错误而非语义失败；这类结果永远不会通过，但汇总脚本把它算作环境故障：不进有效分母、该次运行记为不完整。**规则：来源是“控制格不成立”的基础设施错误（`CELL_INFRASTRUCTURE_ERROR`、`nontrigger controls failed`、`did not establish a valid production observation`）不得当环境故障重跑后剔除；单独计为方法失败，或人工复判**，否则这三案会系统性抬高成功率。
3. **需求未表态的实现选择**：个别合法的或可疑的实现形态需求没有规定，评分器接受或拒绝不代表对错（涉及 1088、4604、DAPR 等案例的探针；只记录，未改判据）。13937 的参考实现只比较属主的 Kind，需求原文说被不同资源控制就报错，二者在“另一个同类型属主”的情形不同，该情形不可观察。
4. **被测实现内部符号**：DAPR 与 1411 的评估桥接依赖被测实现的内部符号，重命名这些符号的合法重构可能导致构建失败；12341 把任意 go test 失败统一映射为构建失败。
5. **评估侧隐藏取值在评估时挂进候选容器**，恶意候选在运行时可读；加载器取候选标准输出中最后一行合法观察，敌意候选可在其后伪造一行（诚实日志不受影响）。该风险为推断，未专项实测。
6. **复核局限**：复核每案只写 3–5 个变体（抽样，不是穷举）；复核者与构建者分开，但并非完全隔离（复核者读过构建者文档、使用同一套评分器副本），共同盲区无法排除；另有 7 案未复核、1 案待修；未在真实集群验证 Kubernetes 行为。4604 的错误实现样本偏少，其参考补丁含不被评分的改动。
7. 候选编译/渲染失败仍记执行失败；评分器不支持删除文件；DAPR 等时间敏感案例按规范要求的“三次独立重置”尚未做。

## 5. 环境偏离（P1）
全部回归、复核与冻结前重跑使用**本地评分器工具副本**：去掉 `--cpus`，私有镜像引用映射到本地标签；runner 型案例（13937、17395、4604）使用包内评分脚本加 `docker` 垫片；评分逻辑与包内一致，**未在原生 containerd + cpu-cgroup 环境做抽样复核**。该偏离适用于每一案的所有结果，引用任何结果都要带上。
