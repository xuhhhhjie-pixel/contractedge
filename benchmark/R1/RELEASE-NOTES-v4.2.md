## 4. 剩余风险（冻结不等于这些风险不存在）
回归共数千次评分器运行，期望与结果仍不一致的变体属于下列类别（均已知并被接受）：
1. **helm 上下文不可观测**：把修复挂在 `.Release.IsInstall`、`.Capabilities.*` 上的错误实现，在 `helm template` 的固定上下文下与正确实现不可区分，评分器可能判通过（占不一致的大多数）。
2. **checksum 注解与随机值**：`checksum/*` 注解只比有无；随机值检查只覆盖少数案例的隐藏输入，公开 cell 渲染一次、不做该检查；部分案例的随机字段不检查。
3. **`tpl` 求值**：对值再做模板求值的写法，在输入值不含模板记号时不可区分。
4. **“允许新增”口径**：对目标对象“新增无害字段不判错”，故少数有害的新增仍可能被放过。
5. **对象种类与默认值路径**：个别案例的对照输入只禁止特定对象种类；个别默认值路径没有对应输入。
6. **评估侧私有簿记**：评分在少数输入上使用评估侧私有的簿记分隔，若候选获知其内容并刻意利用，可能影响判定；因需要事先知道私有内容，现实概率很低。
7. **引擎口径**：基线比较对 `null` 与 `{}`、无名列表项内新增等边界的口径不完全一致，存在少量误拒倾向（独立复核未造出确认合法而被拒的实现）。
8. 候选渲染失败记为执行失败而非语义失败；评分器不支持删除文件。
9. **同模型族盲区**：判据、变体与期望由同一模型族的 agent 起草，复核也由 agent 完成；未在真实集群验证 Kubernetes 对重复键等输入的实际行为。
10. 120 的参考修复是从上游修复提交做的任务投影，与上游提交**不逐字相同**（来源说明保存在完整包的私有来源记录里）。
